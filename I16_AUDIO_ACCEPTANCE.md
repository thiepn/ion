## Implemented in existing source authorities

1. **One original RaceAudio engine, not a parallel sound system.** `src/audio.ts` remains the only WebAudio owner, opt-in via the existing SOUND ON button, muted by default at each new browser session. It synthesizes sound **entirely** from local WebAudio oscillators and a deterministic procedural mono airflow buffer. It fetches zero audio samples, creates zero media files, stores no telemetry and does not modify engine scoring/physics.
2. **Driving feel:** the original engine saw and harmonic triangle oscillators respond to actual `RaceSnapshot.speedKmh`, existing `InputController` throttle/brake and original `isBoosting` / `padSurge`. Speed and acceleration smoothly raise motor pitch, harmonic and low-pass cutoff; braking reduces pitch and subtly increases airflow hiss. Dynamic gain and upper bounds protect against uncontrolled amplitude. The faint wind/road-airflow layer is a buffered locally seeded noise signal filtered within the **same master mix**, active only while genuinely racing. No new background track or unlicensed recording.
3. **Authentic event cues:** countdown tick/GO, actually earned source `raceEvent.serial` S1–S3, legitimately completed laps and real current-PB distinction, genuine pad counter increments at original `BOOST_PAD_T`, fast shield-damaging rail impacts, and true official race completion or shield failure. A `Set` with seven-voice cap prevents rail scrapes or repeated event polling from spawning unlimited voices. One-shots route through the **same** global master bus rather than bypassing mute/volume.
4. **Lifecycle correctness:** the existing enable click continues to acquire user-gesture permission; no autoplay or hidden force-unlock. Disabled audio sets master and continuous voices silent, clears pending cue voices and suspends the AudioContext. A cancellation serial protects against old `resume()` resolutions winning an ON→OFF→ON race; obsolete `suspend()` is awaited/reconciled. Muted/hidden snapshots still advance `raceEvent.serial` ownership so re-enabling cannot replay previously earned gates. The existing `App` visibility listener now suspends audio in hidden tabs and attempts to resume only already-user-enabled audio on return; foreground auto-resume may still be denied by browser policy until another user gesture. End-of-race, pause, renderer failure and menu use the existing source snapshot to quiet continuous sound. `dispose()` stops oscillators/noise, disconnects routing, closes AudioContext; `reopen()` respects React StrictMode lifecycle.
5. **User-owned volume:** a clearly labeled 25/50/75/100% synth volume selector in the **original** pilot manual and paused race menu, with minimum 44px touch control and focus outline, shares one `RaceAudio.setVolume` implementation. The preference `ion-i16-audio-volume` stays only in localStorage, not an account or cloud service. It does **not** opt the player into sound next session; enabling is separately required every time. Existing craft, controls, camera, UI and privacy remain.
6. **Restrained visual speed cue:** the original `SpeedWake` Three.js instanced effect is reduced in instance count (QUALITY 50→36, PERFORMANCE 18→12), activates at real >31 m/s rather than >21, and scales subtle streak opacity/length with actual speed and native boost. It is disabled when the already-detected user `prefers-reduced-motion` is true, reused through the existing `World` prop. ChaseRig's original speed FOV, physics, player craft, score and lighting are untouched; no fullscreen screen blur, fabricated haptics or new renderer.
